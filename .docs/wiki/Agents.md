# Agents

Outside agents (Claude Code, Codex, Cursor and any MCP client) edit what is open in the window through three layers that share one set of rules: the MCP tools, the command catalogue and Agent Connect.

| Source path | What lives there |
| --- | --- |
| `backend/app/routers/mcp.py` | The MCP server (`/mcp`): 140 tools (129 in `TOOLS` and 11 from `mcp_pack.py`), each description ending in a "Use when" line; `/mcp?tools=core` lists the 31 most used for clients that cap tools |
| `frontend/src/automation/agent-bridge.ts` | The window side: polls the engine for tool calls, runs them through the engine and the catalogue, answers |
| `frontend/src/automation/catalogue.ts`, `command-meta.ts` | The command catalogue: every registered command, `tool.select.*`, `tool.options.*` and seven exact actions (`paint.stroke`, `select.rect`, `select.ellipse`, `select.lasso`, `layer.set`, `adjust.apply`, `filter.apply`); the words for each id live in `command-meta.ts` |
| `backend/app/routers/commands.py` | `POST /api/commands/catalogue` (the window mirrors its catalogue to `commands-catalogue.json` in the data folder), `GET /api/commands`, `GET /api/commands/{id}`, `POST /api/commands/{id}` |
| `setup/cli.py`, `setup/cli_offline.py` | `./formvis cli list|describe|run`: the same catalogue from a shell; a risky command needs `--yes`. `droplet FILE.fvdrop pictures` runs a saved droplet; `serve` is the JSON-lines session (see the manual); `stack`, `contact`, `fit`, `photomerge` and `hdr` need no window |
| `backend/app/services/agents.py`, `routers/agents.py` | Agent Connect: master switch, a policy per client (allow, ask, deny), sessions, approvals that time out after 120 seconds, an activity log of 200 entries, and a WebSocket at `/api/agents/stream` |
| `frontend/src/ui/panels/agent-connect.ts` | The panel: master switch, a row per agent with its policy, approval sheet, activity feed, Follow Agent, Stop |
| `setup/agents.py` | `./formvis agents install` sets up the three clients with every skill; `sync` regenerates the references that follow the code, mirrors `.claude/skills` to `.agents/skills`, and writes `agents/manifest.json` (what the app offers agents: every MCP tool, which are read-only, which wait for approval, the skills and their sub-skills, the dock, the extension host), the file the family's shared spec is built from; `sync --check` fails on drift, on a manifest that is not what it would write, and on a skill file over the upload gates |

## Skills

- `formvis-harness` for changing formvis's code, with a sub-skill per subsystem.
- `formvis-driving` for editing pictures through the MCP tools, with a sub-skill per action family.
- `formvis-colour-science` for profile, intent, CMYK and Lab questions.
- `formvis-editing` is a pointer to `formvis-driving` and holds the generated tool reference.

Generated by `./formvis agents sync` and never edited by hand: `formvis-editing/references/tools.md`, `formvis-driving/references/commands.md`, `formvis-harness/references/command-map.md` and `tool-map.md`. The commands references need the window to have run once, because the catalogue is built there.

## Rules

- Every agent step is an undoable step in the window; a list of commands is one step.
- Under Ask, a step that writes a file or that undo cannot reverse waits for the person.
- Whether outside agents may edit at all is the Outside agents choice (Preferences > Plugins): Ask, Allowed or Blocked. On Ask, a request opens the dock module's dialog with Deny, Allow once and Always allow; an answer covers only the request shown, Always allow is kept for that one agent name (the agent's own claim), and Blocked is held by the engine and refuses every agent at once. The [Terminal](Terminal) page has the details.
- Only this computer can connect; `/mcp` checks the Origin header.
- Only the formvis window can change what agents may do, answer a question or an approval, or use the terminal dock. The engine makes a window key at each start (`backend/app/core/window_key.py`); every POST, PUT and DELETE except `/mcp`, `/api/window/key` and the two merge routes needs it in `X-Formvis-Window-Key` and is refused with 403 "Only the formvis window can do this" without it, and the terminal, Claude Code and agent sockets must send it as their first message. Run from source, the first page to ask gets the key; the desktop app hands it to its own window.
- The saved choice (`agents.json` in the data folder) is sealed. Changed outside formvis, it reads as Ask again, and Agent Connect and Preferences say so once.
- formvis's own command line (`./formvis cli`, `./formvis headless`, `./formvis mcp`) goes in through `/mcp` as an outside agent and is asked about like any other. A script that used to change the agent setting through the engine must now have the person set Outside agents to Allowed in the window (Preferences > Plugins) first.
- After changing the tools in `mcp.py` or the commands in the window, run `./formvis agents sync` (with `backend/venv/bin` first on the path); the engine tests run `--check`.
