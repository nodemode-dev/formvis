# demo HASHOUT_LOG

Living log for the offline browser demo. Entries are anchored by file and symbol.

## Real media, masks, text and the photo tray · _v2.0.0 (demo/src/media.ts, poster.ts, text.ts, model.ts, compose.ts, ui.ts, demo/assets/media/)

- Why: the demo opened on a generated harbour and did not read as work a person made. It now opens on a finished poster built from Pexels photographs, with the layer structure of real work. The owner's verdict was that the first screen must look like a real project.
- Packs, not files: `file://` blocks fetch and taints a canvas that has drawn a file image, and the compositor reads pixels. Each photo is one script, `assets/media/[name].js`, that sets `window.FV_MEDIA[name]` to data URIs; `loadPack` injects the script tag on demand and `packImage` decodes a URI through `Image.decode` into a canvas (a data URI does not taint). Only the six tray previews are plain files, because an `<img>` that is only displayed needs no pixel access.
- Masks: a pixel layer has an optional `mask` canvas whose alpha is the visibility, with its own `mrev` and frozen copy so history shares unchanged masks the way it shares pixels. The compositor draws the layer into a scratch canvas, applies the mask with `destination-in`, and blends that (`bakeMask`). Masks ship as grey PNGs and `packMask` turns luminance into alpha. Rotate, flip and image size transform the mask with its layer. Merge down bakes it. PSD export writes the baked pixels because the PSD layer-mask semantics were not verified in ag-psd.
- Mask painting: clicking the mask thumbnail sets `maskTarget`; `dab` then paints on the mask canvas (Brush reveals, Eraser hides). The row uses the application's own `.cv-layer-masks`, `.is-mask-target` and `.is-pixel-target` rules.
- Text: a pixel layer with a `text` spec (`src/text.ts`) re-rendered into its own canvas on every control change; fonts are the bundled Inter and JetBrains Mono, awaited with `document.fonts.load` before the first draw so there is no fallback flash. Rotate and resize turn a text layer into plain pixels (`text = null`).
- The masks were computed once, offline, with OpenCV: the mountain mask is the area at or below the first ridge pixel of each column, found from the colour distance to the row's sky colour; the balloon mask is GrabCut with filled holes and a feathered edge; the mist mask is a sine gradient. The scripts are not shipped; the results are the PNGs inside the packs.
- Zero flash: the shell is built and revealed once with a placeholder document of the poster's size, and `.dv-loading` fades over the canvas in place. When the packs decode, `store.load` swaps the document and the keyed rows reconcile; the sheet never changes size. If a pack fails the generated sample opens and a toast says why.
- The Undo and Redo buttons stayed disabled after a brush stroke because `Store.checkpoint` pushed history without telling anyone. It now emits `history`, and the store handler refreshes the two buttons.
- Photos tab: a second tab in the Properties column holds six cards (thumbnail in a fixed 4:3 box, title, photographer, Open and Place). Place fits the photo inside the document and centres it. The tab only toggles `hidden`; neither body is rebuilt.
- Declined here on purpose: painting selections, Content-Aware anything, vector type. None of the declined patent features appear.

## The offline demo · _v1.99.7 (demo/, frontend/vite.demo.config.ts, frontend/package.json "demo" script)

- Why: show the layered editor working on real input in a browser with nothing installed and nothing started. The whole app (`frontend/src/app.ts`, about 6,600 lines, workers, GPU paths, WebAssembly fetches, an engine on port 8190) cannot run from `file://`, so the demo is a small window written for it that imports the real stylesheets, icon module, brand mark and engine modules.
- Reused unchanged: `styles/tokens.css`, `shell.css`, `panels.css`, `dialogs.css`, `light-mode.css`, `scrollbars.css`; `ui/icons.ts` (`icon`), `ui/brand.ts` (`brandMark`), `version.ts`; engine `blend.ts` (`blendPixels`), `types.ts` (`LAYER_BLEND_MODES`, `canvasBlend`, `compositeOp`), `kernels.ts` (`levelsKernel`, `exposureKernel`, `gradientMapKernel`), `adjust.ts` (`hsvKernel`, `autoLevels`, `desaturatePixels`, `equalizePixels`), `adjust-params.ts` (`PARAM_ADJUSTMENTS`), `filters.ts` (`gaussianBlur`, `motionBlur`, `unsharpMask`, `addNoise`, `histogram`), `io/tiff-browser.ts`.
- The page script is a classic IIFE, not a module: Chrome refuses module scripts from `file://`. `vite.demo.config.ts` sets `output.format` to `iife`, inlines dynamic imports, and its `formvis-demo-classic-script` plugin rewrites the emitted tag to `<script defer>`. Asset names are fixed (`assets/demo.js`, `assets/demo.css`) so a rebuild overwrites instead of accumulating hashed files.
- `src/shim/wasm-kernels.ts` replaces `engine/wasm-kernels.ts` through the `formvis-demo-wasm-shim` resolver. The real module fetches `.wasm` files, which `file://` forbids and which would log errors; every call answers false or null so the TypeScript twins run, as they do whenever a chunk has not loaded.
- `resolve.alias` points `ag-psd` and `@fontsource` at `frontend/node_modules`, because `demo/` has no `node_modules` of its own. No dependency was added; ag-psd, utif2 and the fonts are in `frontend/package-lock.json` and `NOTICE.md`.
- Document model (`src/model.ts`): pixel layers hold a canvas and an offset; adjustment layers hold an adjustment id and its values. History shares frozen layer canvases between snapshots (`rev` counts pixel changes) so 24 steps cost little. A filter dialog takes one checkpoint on open and `dropLast` removes it on Cancel.
- Compositor (`src/compose.ts`): canvas blend modes use `globalCompositeOperation`; the ten pixel modes and four extra modes go through `blendPixels`; adjustment layers run their kernel on everything below and mix by opacity. Adjustment kernels are cached per layer by id and values.
- Zero-flash: the shell is built once before `body.app-ready` reveals it; layer rows are keyed and reconciled in place (`syncRows`), thumbnails redraw only when a layer's `rev` changes, the properties panel rebuilds only when the selected layer changes, the display canvas is resized and repainted in the same frame, and the canvas and layer thumbnails reserve their size.
- PSD: opened with `readPsd` (groups are flattened, blend names map by replacing spaces with hyphens), saved with `writePsd` (compressed; adjustment layers are not written as layers, only baked into the merged preview; the four extra blend modes are written as Normal).
- Images larger than 3200 px on the long side are scaled down on open (`MAX_SIDE` in `src/io.ts`) to keep the CPU compositor responsive.
- Declined here on purpose: selections, masks, paths, type, layer styles, smart objects, Selection-Aware Fill, Liquify. None of the declined patent features appear.
- Verified: `npx tsc --noEmit -p ../demo` clean; `npm run demo` builds; headless Chrome from `file://` shows no console output, loads the sample, and runs an adjustment layer, a filter, a brush stroke, Auto Tone, a pixel blend mode, undo, a PSD export and reopen, a JPEG estimate, a PNG open, a rotate and an invert.
