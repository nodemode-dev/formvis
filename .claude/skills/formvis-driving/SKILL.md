# formvis-driving

formvis is a layered image editor running on this computer. Its MCP server (named `formvis`) gives you picture tools and a command catalogue that act on what is open in its window, so every change becomes an ordinary, undoable step the person can see. The tools are the hands; this skill is how to use them well. The exact parameters of every tool are in `../formvis-editing/references/tools.md` and every window command is in `references/commands.md` (both generated by `./formvis agents sync`; do not edit them).

## The command catalogue

Anything the window's menus, tool rail and options bar can do is a command with an id. `list_commands` (narrow with `group` or `text`) and `describe_command` read the catalogue; `run_command` runs one and `run_commands` runs a list as a single undo step. Seven actions take exact values: `paint.stroke` (a brush, pencil, eraser, mixer, smear, dodge, burn or sponge stroke through given points with pressure), `select.rect`, `select.ellipse`, `select.lasso`, `layer.set`, `adjust.apply` and `filter.apply`; `tool.select.<tool>` and `tool.options.<tool>.<option>` choose and set tools. `get_selection` and `get_layer_tree` read the selection and the layers. Prefer a dedicated picture tool when one fits, and the catalogue for the rest.

## The loop for every task

1. `get_document`: size, resolution, mode, depth, profile, the layers bottom to top with ids and kinds, the active layer, the selection, and the open documents. Nothing open? `new_document` or `open_file` with an absolute path.
2. `get_image`: look at the picture before touching it. Check again after each change; tools report what they did, only the picture shows whether it looks right. The person is watching the window.
3. Work in small steps, each one undoable. `undo` takes `steps` (1 to 100); `redo` the same.
4. A new element goes on its own layer, so it can be moved or removed later.
5. Finish by delivering: `export_image` for a flat file, `save_project` for a `.fmv` that stays editable.

The server's `edit_strategy` prompt holds the decision tree in ten lines; fetch it if you are unsure which family applies.

## Rules that apply everywhere

- The active layer is what most tools act on: `set_layer` with `active: true` chooses it. Tools that take an `id` select that layer for you.
- Filters need pixels. A text, shape or smart-object layer must go through `rasterize_layer` first; the filter's error names the id.
- Adjustments are layers that change what is beneath them without changing pixels (`add_adjustment`), and can be tuned later (`set_adjustment`).
- Select before `generative_fill` or `fill`; with nothing selected, `fill` fills the whole active layer.
- Paths are absolute (`~` works), the folder must exist, and `save_project` and `export_image` replace an existing file. Ask before replacing a file you did not create.
- Colours are `#rrggbb`. Positions are pixels from the picture's top-left. Layer `x` and `y` are the layer's top-left.
- Generative tools prefer this computer (LaMa, Krea 2, FLUX.2 klein, Real-ESRGAN) and only then fal, which asks the person because it costs money. Never pass `model: "fal"` unless the person chose it.
- There are no dedicated MCP tools for layer masks by hand, layer groups, text editing after creation, mode conversion or warps, and brush strokes go through `paint.stroke`. Look for a command with `list_commands` before saying something cannot be done; each sub-skill says what to do instead, and when nothing fits, tell the person it can only be done by hand in the window.

## When something fails

Every formvis error says what to do next. Read it, do that, retry.

| What you see | What it means | What to do |
| --- | --- | --- |
| No formvis tools at all | The MCP server is not connected in this client | Tell the person to run `./formvis agents install` in the formvis folder, or approve the project's MCP server, then restart the client |
| "formvis is not open" | No window, and one could not be opened | Ask the person to run `./formvis boot` (or open the formvis app), then retry |
| "did not allow outside agents" | The person clicked Not now | Ask them to allow it (the question in the window, or Preferences > Plugins), then retry. Do not retry in a loop: a refusal holds for ten minutes |
| "No layer has the id" | A stale or mistyped id | `get_document` again and use the ids it gives |
| "No document is open" | Nothing to act on | `new_document` or `open_file` |
| A tool name that does not resolve | A near-miss name | Use the exact names in `tools.md`; they are case sensitive |
| "formvis did not answer in time" | A long task, or a busy window | Check the window, wait, then retry once |
| A multi-step edit stopped halfway | One step failed | `get_document` and `get_image` to see where it stands; `undo` back if needed; continue from there |

To tell a skill problem from a server problem, call `get_document` directly. If that fails, the problem is the connection or the window, not how the tools are used.

## Setup, for the person

In the formvis folder, `./formvis agents install` sets up Claude Code, Codex and Cursor for their user account (the MCP server and the `formvis-editing` skill), so pictures can be edited from any folder. Inside the formvis repository nothing is needed: `.mcp.json`, `.cursor/mcp.json` and `.codex/config.toml` already point at `./formvis mcp`, which starts the engine when it is not running. The first edit asks the person once, in the formvis window, to allow outside agents.
