# demos/design HASHOUT_LOG

Living log for the type and design demo. Entries are anchored by file and symbol.

## The design kit, three artboards and page-side encoders (demos/design/src/session.ts, shim/api.ts, shim/encode.ts, vite.config.mjs)

- Why: the owner approved the first demo and asked for three demos per app that touch different aspects. This one is type and design: a social and event graphic made with Type, shapes, layer styles, smart filters and the Filter Gallery, artboards of several sizes, Export As and a layered PSD.
- Same approach as `demo/`: the real window, not a look-alike. `vite.config.mjs` keeps its root inside this folder (`src`) and writes its output into this folder with `emptyOutDir` false. `src/index.html` is a stub; the `formvis-design-page` plugin replaces it with `frontend/index.html`, rewrites the stylesheet links to relative paths into `frontend/src/styles/`, and adds the `data-demo="building"` hold so nothing paints until the session is ready. Workers are inlined, the output is a classic script, and the WebAssembly kernels use `demo/src/shim/wasm-kernels.ts` by path (read only). `demo/src/media.ts` is imported for `loadPack` and `packImage`; packs are read from `./assets/media/` relative to the page.
- Session: `session.ts` creates a document, three artboards through `newArtboard` (the new artboard becomes the active layer, so the layers that follow land inside it through the engine's `parentForNew`), photographs through `insertRasterLayer` then `convertToSmartObject` then `addSmartFilter('filterGallery', ...)` with `lib.filterGallery.effects` listing Diffuse Glow and Film Grain, shapes through `addShapeLayers` with `boxedShapePath`, type through `createTextLayer` (its y is the first baseline), and styles through `setLayerEffects`. The blank base layer is deleted last. Artboards are created cover, story, post so the Layers panel lists Post last-created at the top of its group order and the first artboard on the canvas is the Post.
- Fonts: the application registers Bebas Neue, Playfair Display and Montserrat lazily from `fonts/<slug>/<slug>-<weight>.woff2` relative to the page, so those three folders are copied from `frontend/public/fonts/` into this folder. `ensureBundledFont` is awaited before each type layer so there is no fallback flash.
- Encoders: Export As sends PNGs to `/io/encode` for TIFF, BMP, TGA, QOI, ICO, PNM and PDF. `shim/encode.ts` writes them from canvas pixels (uncompressed TIFF with resolution tags and extra alpha sample, 32-bit BMP with V4 header, 32-bit TGA, QOI, PAM, PNG-in-ICO, JPEG pages in a hand-written PDF with a cross-reference table). PNG, JPEG and WebP use the canvas. Anything else answers 503 with the application's own message. Checked by decoding each output with Pillow and ImageMagick and rendering the PDF with pdftoppm.
- Links: `links.ts` adds one small `nav` naming the three demos in the title bar, in the application's text colours and tokens, hidden while the window is held and below 1120 px. It uses `var(--z-chrome)`.
- Declined here on purpose: nothing was added to the application; none of the declined patent features appear, no icon or sparkle was introduced, and no vendor feature name appears in a label.
- Verified from `file://` in headless Chrome: no console error (one Chrome warning that no WebGPU adapter exists, as in the app on a machine with none), no non-local request; at 4x CPU throttle the window stays hidden through the build and changes once to visible with all 38 layer rows, and nothing changes in the four seconds after.
